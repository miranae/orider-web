# 앱 #2367 트레이닝 탭 반복 인증 — 운영 반영 후보

## 확인한 원인

2026-09-06 운영 `https://orider.co.kr`의 엔트리 `index-sZEndo8c.js`가 참조하는
`EmbeddedBootstrapRoot-CjLPDXzs.js`를 직접 확인했다. 이 번들은
`bootstrap.ready`에 `{contractVersion: 1}`만 전송하며 `host.surfaceSelected`를 지원하지 않는다.

앱 `dev`의 `5c95960b7`에는 Android/iOS 공통 `RetainedTrainingHostReducer`와
셸 수명의 단일 트레이닝 호스트가 이미 있다. capability가 없으면 retained 호스트를
파기한 뒤 legacy 호스트로 전환하는 계약이다. legacy 호스트는 탭 이탈 시 파기되므로
메모리 전용 웹 인증도 사라지고 다음 진입에서 핸드오프가 반복된다.
`isActive=false` 자체는 정상 retained 호스트를 파기하지 않는다.

Galaxy S25 Ultra `R3CY201D7TR`의 기존 로그에서도 12:12:04 피트니스 재선택
(`load_state=warm`) 후 12:12:05 핸드오프 발급, 12:12:09 계획 선택 후
12:12:10 핸드오프 발급이 확인됐다. `warm`은 탭 방문 이력이며 WebView 재사용의 증거가 아니다.

웹 PR #879~#883은 dev에 병합됐지만 운영에는 반영되지 않았다.
승격 PR #896은 누적 dev 커밋의 DCO 누락으로 중단됐고 별도 UI hotfix만 배포됐다.

## 반영 범위

운영 main `2b22acfd1748fdcdfce5b1290d8b9e04d66677c4` 위에 다음 변경을 적용한다.

| 기존 PR | 커밋 | 역할 |
|---|---|---|
| #879 | `43c813a` | 로딩 단계 계측 |
| #880 | `39c4841` | 인증된 부분 셸 공개 |
| #881 | `733b2b1` | 단일 호스트 내 화면 선택과 비활성 표면 해제 |
| #882 | `7e76ad8` | 세션 메모리 캐시와 선택 requestId 계약 |
| #883 | `1afd295` | 파생 지표 대기가 핵심 콘텐츠를 막지 않도록 수정 |

앱 코드, 백엔드, 영속 캐시 변경은 없다. 기존 main UI hotfix를 보존한다.

후보 리뷰에서 `surface.shellReady`가 선택 requestId를 전달하지 않는 통합 누락도
확인했다. Android/iOS는 두 번째 선택 이후 무ID 신호를 무시하므로, 현재 선택의
requestId를 함께 전송하도록 보완한다. 초기 선택의 무ID 호환성은 유지한다.
회귀 테스트는 피트니스 → 계획 → 비활성 → 피트니스 전환과 이전 프레임의 지연 실행을 검사한다.

추가 리뷰 반영:

- 분석 섹션의 지표 준비·오류 상태는 선택한 종목의 활동만으로 계산한다. 통합 화면은 전체 종목을 기준으로 유지한다.
- 피트니스·계획의 초기 캐시 조회는 지연 초기화로 처리한다. 같은 키의 재렌더링마다 전체 DTO를 복제하지 않으며, 사용자·종목·언어 등 모델 키가 바뀌면 기존 effect가 새 캐시를 읽는다.

## 로컬 검증

- 기존 변경 5개 적용 후 전체 Vitest 414파일 / 3,504개, 스크립트 테스트 23개 통과.
- 웹 lint·품질 예산·프로덕션 빌드 통과.
- shellReady 추가 회귀는 수정 전 실패·수정 후 통과. capability 광고 제거 시 기존 테스트도 실패했고, 복원 후 Bootstrap 전체 26개가 통과했다.
- 종목 격리·캐시 재렌더링 회귀는 수정 전 피트니스 3건·계획 1건 실패를 확인했고, 수정 후 관련 화면·브리지·훅 테스트 14파일 / 174개가 통과했다.
- 독립 코드 리뷰 통과. 계획 모델의 원자적 갱신으로 도달하지 않는 일부 부분 로딩 분기는 비차단 정리 대상으로 기록한다.
- 앱 Android/iOS 정적 계약 패리티 검사 통과. 앱 코드는 변경하지 않았으며 앱 빌드는 실행하지 않았다.
- 운영 반영 후 실제 인증 재사용·전환 시간 검증은 아직 수행하지 않았다.

## 운영 완료 판정

1. 승인 후 `scripts/merge-pr.sh` 전체 게이트를 통과해 main에 병합한다.
2. 저장소 릴리스 절차로 운영 Hosting에 반영하고 실제 제공 번들의 capability를 확인한다.
3. 최신 앱에서 프로세스를 새로 시작하고 피트니스 → 홈 → 피트니스 → 계획을 왕복한다.
4. 최초 인증 이후 정상 탭 왕복에서 핸드오프가 반복되지 않는지, 부분 셸과 콘텐츠가
   나타나는지 Android/iOS 각각 확인한다. 로그아웃·UID 변경 시 기존 콘텐츠 폐기도 확인한다.

운영 배포와 양 플랫폼 실기 재검증 전에는 앱 #2367을 해결 완료로 닫지 않는다.
