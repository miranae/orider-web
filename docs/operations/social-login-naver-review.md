# 네이버 로그인 공개 검수 및 웹 배포 준비

상태 기준: 2026-10-18. 웹 PR #1206은 Draft이며 `dev` 대상이다. 검수 준비는 머지·stage 배포·main 승격·운영 배포 승인을 포함하지 않는다.

- 서비스 URL: https://orider.co.kr/ko
- 개인정보처리방침: https://orider.co.kr/ko/privacy
- 이용약관: https://orider.co.kr/ko/terms
- 계정 삭제 안내: https://orider.co.kr/ko/account-deletion

- 전체 계정 삭제: 계정 삭제 페이지에서 요청하고 서버의 처리·완료 상태를 확인합니다. 연결 해제만으로 전체 O-Rider 계정이 삭제되었다고 안내하지 않습니다.

## 실제 검증 범위와 제출 시 표기

실제 네이버·카카오 인증 및 연결 해제 API를 호출한 브라우저 검증은 완료했다. Firebase 계정·프로필·연결 매핑은 격리된 `demo-orider-social` 에뮬레이터에서만 생성·변경했다. 등록된 콜백 `http://localhost:5173/auth/social/callback`을 사용했으며 테스트 후 기존 개발 서버를 복원했다.

확인한 경로:

1. 네이버 ID만 제공한 신규 로그인 → 프로필 생성 → 온보딩 건너뛰기 → 설정.
2. 같은 계정에 카카오 연결 → 로그아웃 → 카카오 로그인 → 같은 UID 유지.
3. 각 제공자의 실제 연결 해제 → 재연결 성공. 마지막 로그인 수단의 연결 해제 차단.
4. 최종 사용자·프로필 각 1개, 제공자 연결 2개로 복원.
5. 미요청 콜백 거부, 콜백 주소의 code/state 제거, 홈 복귀.

이 증적은 **개발 환경 검증**으로 표기한다. 운영 사이트에서 네이버 버튼이 이미 보이거나 운영 로그인 검증을 마쳤다고 기재하지 않는다.

## 검수 첨부 자료 수집 순서

네이버에 별명·사진 조회 권한이 선택되어 있다면 선택 정보도 활용처 자료가 필요하다. ID만 제공한 테스트 캡처를 별명·사진 활용 증적으로 제출하지 않는다. 별명·사진 제공에 동의한 실제 테스트 계정으로 가입 후 프로필 활용을 캡처하거나, 실제 제품에 불필요하다면 콘솔 조회 권한을 ID만 남기는 방향을 별도 결정한다.

스크린샷은 사용자가 제출에 동의한 최소 정보만 포함한다. 프로필 사진·이름·연결 회원번호·인증 코드·state·토큰·API 키·계정 외 데이터가 포함된 파일을 공개 Git에 커밋하지 않는다. 제출용 원본은 로컬 임시 폴더에 보관한다.

## 로고와 버튼

- 기존 공개 브랜드 원본: `public/favicon.svg` 및 `public/app-icon.png`(512×512 PNG).
- 검수용 업로드 파일: [`assets/orider-logo-140.png`](assets/orider-logo-140.png) — 기존 `public/favicon.svg`를 렌더링한 140×140 PNG, 18,621 bytes.
- 로고 제출은 기존 브랜드 원본을 사용하며 새 브랜드 이미지를 생성하지 않는다. 140×140 PNG가 필요하면 기존 SVG를 해당 크기로 렌더링하고 파일 크기·화질을 확인한다. 업로드 화면의 실제 제한이 우선이다.
- [네이버 공식 버튼 가이드](https://developers.naver.com/docs/login/bi/bi.md)의 현재 지정 녹색은 `#03A94D`이다. `--naver` 토큰과 생성 CSS에 반영했다. 현재 “네이버로 계속하기” 문구는 로그인 목적을 유지하며 N 로고와 함께 표시된다.

## 배포 전 확인과 stage 제약

웹은 서버 PR miranae/orider-g1-web#3249의 API와 함께 출시해야 한다. 서버의 Secret 값은 문서·명령줄·첨부 자료에 복사하지 않는다.

현재 stage Hosting workflow(`.github/workflows/deploy-stage.yml`)는 `dev` push 또는 `dev`의 수동 실행만 허용한다. Draft 브랜치를 그대로 배포하는 lane으로 간주하지 않는다. Stage runtime은 공유 Firebase 인증·데이터를 사용하고 Functions endpoint는 `https://asia-northeast3-orider-dev.cloudfunctions.net`으로 분리하므로 에뮬레이터와 같은 격리 환경이라고 안내하지 않는다.

검수자에게 stage에서 직접 로그인하게 하려면 별도 승인 후 서버와 웹을 일관된 stage로 배포하고, 네이버·카카오 콘솔 및 서버의 정확한 stage callback 허용 목록, stage Secret/IAM, Auth authorized domain, App Check 설정을 함께 검증해야 한다. 현재 등록된 localhost/운영 콜백만으로 stage 로그인이 가능하다고 가정하지 않는다.

운영 배포 전에는 보호된 머지 게이트, 서버 제공자 revoke/삭제 lifecycle, 웹 production App Check, origin callback, 운영 Hosting entry hash, 로그인·재로그인·연결·해제·계정 삭제 재인증을 순서대로 확인한다. 운영은 `main`에 포함된 `v*` 태그와 production environment 승인을 거친 Hosting workflow가 담당한다. 준비 단계에서는 merge, tag push, workflow 실행, Firebase deploy를 수행하지 않는다.
