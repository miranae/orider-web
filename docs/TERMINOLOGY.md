# 화면 용어 규칙 — "컨디션"과 훈련 지표

이 문서는 웹·앱·서버(코치·LLM 문구 포함)가 함께 따르는 화면 용어의 정본이다. 문구를 추가하거나 바꿀 때, LLM 프롬프트에 용어를 지시할 때 이 규칙을 먼저 확인한다.

- 결정일: 2026-10-18
- 배경 분석: orider-g1-web `docs/analysis/2026-10-18-home-today-strip-ux-analysis.html`
- 관련 설계: [`HOME_TODAY_PLAN_INFORMATION_ARCHITECTURE.md`](HOME_TODAY_PLAN_INFORMATION_ARCHITECTURE.md) (:22-24 사고 사례, :247 폼 표기, :287 모순 표현 금지)

## 1. 규칙

> **"컨디션"은 지표·화면·숫자의 이름으로 쓰지 않는다.**
> **사용자가 느끼는 몸 상태를 일상어 문장으로 말할 때만 쓴다.**

판별 기준은 하나다. **그 말 옆에 숫자나 계산값이 붙거나, 그 말이 화면·메뉴·카드를 가리키면 쓰지 않는다.**

### 왜

- 사용자는 "컨디션"을 "오늘 내 몸 상태"로 읽는다.
- 화면에서 "컨디션"이라 부르던 값은 대부분 TSB(폼)였다. TSB는 최근 훈련 부하로 계산한 값이라 수면·통증·HRV를 반영하지 않는다.
- 같은 화면에서 "컨디션이 안정적"과 "깊은 피로"가 동시에 표시된 사고가 있었다(IA :22-24).
- 서버의 코치 용어집과 LLM 프롬프트도 TSB를 "컨디션 균형", "컨디션 여유"로 부르게 지시하고 있었다.

## 2. 대체어

| 가리키는 것 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| 피트니스 화면 전체(탭·메뉴·홈 카드·링크) | **훈련 상태** (예: 코치 > 훈련 상태, "훈련 상태 보기 →", "통합 · 훈련 상태") | 컨디션 |
| TSB (CTL − ATL) | **폼**, 처음 나올 때 **폼 (TSB)** | 컨디션, 컨디션 여유, 컨디션 균형 |
| CTL·ATL·TSB의 추이 | **훈련 부하 변화** | 컨디션 변화 |
| 폼 구간을 해석한 문장 | "폼이 …", "체력과 피로의 균형이 …" | "컨디션이 …" |
| 부하 재계산 중 상태 | "최근 기록 반영 중…" | "컨디션 반영 중…" |
| 사용자가 느끼는 몸 상태 | **컨디션** 또는 **몸 상태** (문장 안에서만) | — |
| 앞으로 붙일 HRV·수면 기반 지표 | **준비도** (지표 이름). 설명 문장에서는 "오늘 컨디션"이라고 풀어 써도 된다 | 컨디션 점수 |

영어 문구도 같은 원칙을 따른다. 화면 이름은 **Training status**, TSB는 **Form**, 추이는 **Training load trends**를 쓴다. 지표를 가리키는 "Condition"은 쓰지 않는다.

## 5. 적용 범위

- **웹**: i18n(ko·en), 화면에 직접 쓴 문구, 매뉴얼 원본(`manual-src/`)과 생성기, 앱 매뉴얼 사본(`public/manual/`), `shared/` 사본의 사용자 문구.
- **앱**: Android `strings.xml`, iOS `Localizable.strings`, shared Kotlin의 사용자 문구.
- **서버**: 사용자에게 나가는 처방·추천 문구, 코치 용어집(`coach-glossary-data.json`), LLM 프롬프트의 용어 지시.
- **바꾸지 않는 것**
  - 경로 `/coach/condition`과 코드 식별자(`condition`, `conditionLink` 등)는 그대로 둔다. 사용자에게 보이는 이름만 바꾼다.
  - 사용자 질문 해석(코치 질의 파서가 "컨디션"을 폼 질문으로 인식)은 유지한다. 사용자가 쓰는 말을 받아들이는 입력 쪽이기 때문이다.
  - 사고 사례를 인용한 문서의 원문.

## 7. 후속으로 정할 용어 (이 규칙의 범위 밖)

- TSB를 "회복 상태 (TSB)", "회복상태 TSB"로 부르는 문구를 "폼"으로 통일할지.
- 체력·피로·폼 표기 형식(`체력 (CTL)` 등) 단일화.
- 홈 상태 동사: IA :890의 4개(계획 유지 · 부하 낮춤 권장 · 회복 권장 · 휴식 권장)와 홈 strip의 "증량 가능 · 유지 권장 · 회복 우선" 정리.
- 오늘 할 일의 이름("오늘 운동" / "오늘의 계획" / "오늘의 워크아웃").
- 앱 하단 탭 "피트니스"와 웹 메뉴 "훈련 상태"의 이름 일치 여부.
