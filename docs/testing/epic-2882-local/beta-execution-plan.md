# R9 웹·서버 베타 실행 계획과 판정 기록

상태: **계획 준비 / 모집·외부 연락·배포·관찰 미실행**. 2026-10-26 KST.
상위: miranae/orider-g1-app#2882. 사용자 지시에 따라 현재 구현·검증은 로컬에서만 진행한다. 이 문서는 참가자가 존재하거나 출시 승인이 났다는 증거가 아니다.

## 대상과 모집 구성

초기 목표는 24명(허용 범위 20–30명)이다. 아래 네 집단에 각 6명을 배정하는 초안이며, 실제 모집 가능성에 따라 제품 책임자가 조정한다. 한 참가자는 주 집단 하나에만 집계한다.

| 주 집단 | 인원 초안 | 확인하려는 차이 |
|---|---:|---|
| 유료 Strava 사용 + 파워/심박 센서 | 6 | 기존 분석의 정의·원본 이동·기간 비교 기대 |
| 유료 Strava 사용 + GPS 또는 심박 | 6 | 센서 없는 값, 지도·피드·반응 기대 |
| Strava 미연결 + 파워/심박 센서 | 6 | 자체 원본만으로 분석·공유 완결 |
| Strava 미연결 + GPS만 | 6 | 최소 센서 입력·첫 기록·빈 상태 |

위 구성 안에서 Android 브라우저와 iPhone 브라우저를 각각 최소 8명, 데스크톱 웹을 최소 8명이 사용하도록 중복 배정한다. 이는 웹 브라우저 구분이며 네이티브 앱 검증을 대신하지 않는다. 클럽 신규/기존 회원, 첫 활동/장기 이력도 각 집단에 분산한다. 초대 의사·데이터 사용 동의·기기 보유는 아직 확인하지 않았다.

모집 전 확정할 사항: 모집 채널, 안내/지원 담당자, 시작일과 종료일, 보상 여부, 사용할 환경과 실제 접근 가능한 버전, 개인정보 보관·삭제 기한. 값은 임의로 채우지 않으며 실행 담당자가 기록한다. 외부 연락은 별도 실행 승인이 있을 때 수행한다.

## 참가 준비와 데이터

- 참가자 식별은 B001 등의 가명으로 관리한다. 연락처와 식별자 대응표는 접근 제한된 별도 저장소에 두며 이 저장소에 커밋하지 않는다.
- 참가자 자신의 기록 또는 사용 허가를 받은 원본만 사용한다. 원본 FIT/GPX·좌표·건강 수치·비밀번호·토큰을 설문이나 이슈 첨부물로 받지 않는다.
- 화면 증거는 위치/계정/본문을 가리고, 수치 비교가 필요하면 허용된 동일 원본의 지표·정의·revision만 별도 제한 자료에 기록한다.
- 참가자는 공개 범위와 사진을 확인한 뒤 공유한다. 공개하지 않아도 비공개 분석 과제에 참여할 수 있으며, 공개 거부를 기술 오류로 분류하지 않는다.
- 실제 유료 비교는 참가자 본인 계정에서 직접 확인한다. 로그인 정보 공유를 요구하지 않는다. 유료 서비스에서 확인하지 못한 항목은 미확인으로 남긴다.

## 2주 관찰 일정

시작일은 미정이다. 각 참가자의 관찰 기간은 최소 14일과 실제 라이딩 2회를 권장한다. 미달 참가자를 결과에서 제거하지 않고 노출 기간과 미완료 사유를 기록한다.

| 시점 | 진행 | 남길 증거 |
|---|---|---|
| D0 | 기기·경험·센서·입력 방식 확인, 첫 과제 시작 | 가명, 환경/버전, 참여 동의, 시작 시각 |
| D1–D3 | 첫 라이딩 저장/입력, 공유, 서로 반응 | 과제별 성공/실패/도움, 지연·오류, 복귀 상태 |
| D4–D10 | 두 번째 라이딩, 단일·기간·경로 비교 | 정의 차이 이해, 결측 안내, 원본 왕복, 불만 |
| D11–D14+ | 재사용 의향, 삭제/비공개·알림 제어 확인 | 전체 분모 설문, 미응답, 철회·삭제 처리 |

오프라인/차단/삭제 같은 파괴적 검증은 별도 합성 계정에서 먼저 수행한다. 참가자 기록을 임의로 변경하거나 차단 관계를 만들지 않는다.

## 도움 없이 수행할 핵심 과제

진행자는 처음에는 목적만 읽어주고 조작 순서를 알려주지 않는다. 힌트가 필요하면 시점·내용을 기록하고 해당 과제를 assisted로 분류한다. 기술 장애·자발적 중단·접근 제한은 구분한다.

1. 본인 라이딩을 직접 기록 또는 허용 원본 입력으로 저장하고 사진/본문/공개 범위를 확인한다. Strava 미연결 집단에서도 수행한다.
2. 피드에서 상대의 허용된 활동을 찾아 상세와 프로필을 열고 반응을 남긴 뒤 원래 피드 위치로 돌아온다. 상대 계정에서 반응을 확인한다.
3. 본인 기록의 핵심 수치와 센서 차트를 확인하고, 알 수 없는 값과 측정/추정 값을 구분한다. 수치 정의 설명을 찾아 해석한다.
4. 최근 4주 또는 사용자 지정 기간의 결과와 원본 기록을 왕복한다. 일부 기록만 조사한 결과를 전체 최고로 오해하는지 관찰한다.
5. 제공 가능한 동일 경로 비교를 확인한다. 완전성이 미확인인 데이터에서 개인 최고가 없다는 안내를 이해하는지 기록한다.
6. 알림에서 해당 활동/댓글로 이동하고 설정을 변경한다. 새로고침 후 설정 및 반응 상태를 확인한다.

핵심 성공 지표는 1–3을 모두 unassisted로 끝낸 참가자 수다. 4–6은 기능별 결과로 별도 보고한다. 실험에 포함되지 않은 기능을 성공으로 처리하지 않는다.

## 관찰 기록 형식

기록 한 행: participant_id, cohort, platform, browser_version, environment, web_sha, server_sha, feature_flags_ref, task_id, started_at, ended_at, outcome, assistance, failure_category, evidence_ref.

outcome은 unassisted / assisted / failed / not_started / withdrawn 중 하나다. failure_category는 auth / source_input / permission / network / calculation / navigation / comprehension / other 중 선택하고, 개인정보 없는 짧은 원인을 남긴다. 시각은 timezone을 포함한다. 동일 과제 재시도는 새 행으로 보존하고 첫 시도와 최종 결과를 모두 보고한다.

## 분모와 통과 기준

| 항목 | 계산 | 목표와 미달 처리 |
|---|---|---|
| 핵심 과제 | 1–3 모두 도움 없이 완료한 고유 참가자 / 관찰을 시작한 전체 참가자 | ≥90%. 중도 이탈·미완료를 분모에서 빼지 않는다. 모집만 되고 시작 전 철회한 인원은 별도 공개한다. |
| 계속 사용할 의향 | 피드와 기본 분석 모두 계속 사용할 의향을 표시한 고유 참가자 / 관찰을 시작한 전체 참가자 | ≥70%. 미응답은 긍정으로 보지 않으며 응답자 기준 수치도 별도 표시한다. |
| 정확성 | 사전에 고정한 동일 정의 fixture의 허용 오차 통과 수 / 전체 fixture 수 | 전체 통과. WAP와 NP처럼 다른 정의를 같은 값으로 맞추지 않는다. |
| 공개 범위 | 사전 권한 행렬에서 부적절한 노출 사례 | 0건. 발견 시 해당 경로 공개 중단 후보, 재현·차단·복구 확인 후 재개 판단. |
| 피드/기존 분석 | 고정 기기/망 조건별 30회 이상, 전체 시도·실패 수와 성공 지연 p95 함께 | 피드 ≤2초, 기존 분석 ≤3초. cold/warm 분리. 로컬 결과로 운영 통과를 대체하지 않는다. |

24명이 관찰을 시작하면 핵심 성공 최소 22명, 계속 사용 의향 최소 17명이 필요하다. 실제 분모가 달라지면 각각 ceil(0.9*N), ceil(0.7*N)을 사용한다. 작은 표본의 탐색적 결과이며 전체 한국 라이더 집단으로 일반화하지 않는다.

## 단계별 공개·중단·복귀 판단

현재 단계는 합성 로컬 검증이다. 이후 내부 제한 계정 → 동의한 베타 참가자 → 확대 공개는 각각 제품 책임자가 근거를 보고 판단한다. 지금 자동으로 전환하지 않는다.

- 권한 노출, 원본 손실, 반복 저장 중복/잘못된 수치가 확인되면 해당 기능의 확대를 보류하고 재현 범위·실제 영향·회복 여부를 분리해 기록한다.
- 화면 플래그를 끄는 것만으로 API/Storage 접근이 차단된 것으로 보지 않는다. 되돌릴 버전도 같은 권한 제한을 보존하는지 검사한다.
- 복귀할 artifact/SHA·설정·스키마 호환성을 먼저 확인한다. 알려진 보안 결함 버전으로 단순 롤백하지 않는다. 데이터 복원은 백업과 실제 차이를 확인한 별도 작업이다.
- 비용·지연 기준선이 없거나 측정 망이 바뀌면 미측정으로 표시하고 확대 근거로 쓰지 않는다. 장애 원인과 대응 담당/재개 승인자는 실행 전에 실명 담당자로 채운다.

## 실행 전/종료 기록

실행 전 필수: 담당자·일정·참가 동의, 허용 원본/fixture 정의, 실제 배포 SHA·플래그·계정 범위, 앱 소비자와 강화 규칙의 호환성, 공개 지도·OG·사진 권한 점검, 비용/오류 관측 창, 중단/복귀 책임자.

종료 시 필수: 모집/시작/철회/완료 인원, 집단별 과제·설문 분모, 실패 원인과 열린 결함, 소스별 정확성 표, 실제 기기 증거, 전체 시도 성능 결과, 릴리스 artifact·설정, 출시 대상/제외 기능, 제품 책임자 결정·날짜.

현재 위 실행 기록은 **없음**이다. 로컬 테스트 통과, 이 계획의 작성 또는 PR merge를 베타·출시 완료로 계산하지 않는다. 앱은 후속 범위로 남으며 웹 베타 결과로 앱 수용 기준을 충족시키지 않는다.
