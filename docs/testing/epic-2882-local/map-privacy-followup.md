# R1 공개 지도 보호: 로컬 구현과 검증

## 적용 범위

활동 소유자가 상세 화면에서 시작·종료 지점의 보호 반경을 각각 0–5000m로 설정합니다. 미리보기는 저장 전 상태임을 명시하고 서버와 동일한 필터를 사용합니다. 이는 주행 거리의 앞뒤를 잘라내는 기능이 아닙니다. 시작·종료 지점 주변 원을 다시 통과하는 구간도 제외하며, 안전한 연속 구간 중 가장 긴 하나만 표시합니다. 원본 분석과 소유자의 원본 스트림은 유지합니다.

소유자 컨트롤은 자체 FIT/GPX 원천을 포함하는 모든 소유 활동에 표시합니다. 서버의 현재 원천·소유권·계정 fence·revision CAS가 최종 권한을 결정합니다. GPS를 읽거나 보호 구간을 계산할 수 없어도 양의 반경으로 전체 공개 지도를 숨길 수 있습니다. 원천이 바뀌면 공개 지도는 숨겨지고 다시 미리보기/저장이 필요합니다. 기존 지도 파일 삭제가 끝나지 않은 `revocationPending` 상태는 저장 완료로 표시하지 않고 재저장을 안내합니다.

공유 이미지 생성은 현재 공개 지도만 읽고, 캔버스 생성 후 저장 직전에 공개 범위·revision을 다시 확인합니다. 계정/활동/원천 context가 바뀐 대기 요청은 이미지 생성뿐 아니라 이전 URL 복사도 막습니다. 기존 다운로드/공유 이미지를 회수할 수 없으며 사진 자체의 위치 노출은 별도라는 설명을 표시합니다.

## 캐시된 지도와 비용 경계

피드/프로필 활동 썸네일은 화면에 보이는 동안에만 `getActivityPublicMaps`의 현재 공개 지도를 표시합니다. 기존 카드 props의 원본 경로나 이미지로 되돌아가지 않습니다. 비활성·숨김·재검증 시작 시 지도를 제거하고, 실패 시에도 이전 지도를 복원하지 않습니다. 30초 간격 및 focus/visibility 복귀에 재검증합니다. 공개 상세도 별도 현재지도 상태를 유지하여 오래된 반응 응답이 지도를 다시 넣지 못합니다.

그룹 라이딩에서는 선택되어 보이는 타인 활동만 검증하고 소유자의 원본 hover/분석은 보존합니다. 타인 센서의 시간축으로 보호된 경로에 hover를 연결하지 않습니다. 보호된 경로로 canonical 이미지 업로드를 시도하지 않습니다.

배치는 services identity와 정확한 SDK User identity로 분리하며 결과 캐시는 없습니다. 16ms 창으로 서로 다른 타이머의 요청을 모으고, 요청당 20개씩 한 세션에서 직렬 처리합니다. 200개가 선택되면 10개 요청이며 조용히 20개로 줄이지 않습니다. 서버 1800회/시간 한도는 200개 × 30초 갱신의 1200회/시간에 여유를 둡니다. 각 호출은 AppCheck 준비부터 응답까지 10초 제한을 갖고, 시간 초과 후 준비가 끝나도 늦게 쓰기 요청을 보내지 않습니다. 이미 서버에 전달된 요청은 취소되지 않지만 늦은 결과는 무시합니다.

따라서 이미 보이는 데이터의 변경 감지는 일반적으로 다음 30초 주기와 최대 10초 요청 제한 이내이며 즉시 push 무효화는 아닙니다. 화면을 떠나면 즉시 제거합니다. 이미 외부에 전달한 이미지 회수나 오프라인 외부 복사본 삭제를 주장하지 않습니다.
